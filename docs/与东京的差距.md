# 和东京（jeantimex/tokyo）的差距

对照对象是 [jeantimex/tokyo](https://github.com/jeantimex/tokyo)。那边用 PLATEAU 的实测建筑、地形和航拍贴图，加上程序化窗户、昼夜、沿路车辆和分块加载。本仓库按同样的思路用 OpenStreetMap 和公开高程重写，没有搬它的源码。PLATEAU 不覆盖上海，航拍也不能再分发，所以下面有些差距是数据源决定的，有些是实现还没跟上。

已经对齐的部分不展开：昼夜曲线、后处理链（环境光遮蔽、高度雾、调色、SMAA）、路灯光照贴图、江面倒影、256 米分块、程序化夜窗、右侧通行的车和列车。

## 性能

| 差距 | 现在 | 东京那边的做法 | 看出来的现象 |
| --- | --- | --- | --- |
| 没有几何 LOD | **已改善**：远处 4×4 块瓦片合并成一个网格，地形按距离换粗网格，小件按距离隐藏；楼本身仍是同一份网格，没有粗模 | PLATEAU 自带 LOD，远处用粗模 | 一拖相机就要画很多三角面，远景和近景一样贵 |
| 倒影再画一整城 | **已改善**：地面、道路和街道小件不进倒影，远处楼合并后倒影的绘制次数也少了；静止时仍是全分辨率 | 同类水面反射会降分辨率，不跟主画面抢满幅 | 相机一动就卡。LCP 约 3.2s，INP 约 240ms |
| 阴影和遮蔽每帧都很重 | **已改善**：几何和绘制次数降下来后，静止一帧约 4–15 ms；阴影图 2048 和半分辨率遮蔽本身没变 | 同样的后处理，但建筑有 LOD，单帧几何少 | 停住时帧时间仍然长，点界面会顿 |
| 交通全在主线程 | **已改善**：仍全量步进，但只画相机附近的车（1.6 公里）和人（650 米）；跟车改成线性。还在主线程 | 车辆数量和更新跟视野绑定，远处不模拟到这一密度 | 拖相机时脚本和画图抢主线程 |
| 启动被整包路网堵住 | **已解决**：`roads.json` 在首帧之后才用，路网到了再补人行道底色和车流；地形法线按格网直接算 | 路网和建筑按块加载，不先解析全市道路 | 开发模式下第一次打开要等数据，首屏晚 |

## 贴图

| 差距 | 现在 | 东京那边的做法 | 看出来的现象 |
| --- | --- | --- | --- |
| 没有逐栋航拍 | 墙、屋顶、地面是十来张 CC0 照片平铺；幕墙是 4 张可重复的立面照片 | PLATEAU 每栋楼有自己的墙面和屋顶航拍（那些图不能再分发） | 相邻楼像同一张贴片来回复制 |
| 立面照片和窗格是两套系统 | 矮楼贴整张立面照片，高楼又改回程序化窗格。照片按固定开间重复 | 航拍本身带窗，程序化窗只补没有照片的面 | 金茂、上海中心这种高塔看起来像外壳套了一层切片，没有这栋楼自己的皮 |
| 玻璃没有屏幕空间反射 | 玻璃只反射天空环境贴图和太阳高光 | 有屏幕空间窗户反射 | 幕墙不映出路对面的楼 |
| 天空是解析渐变 | 没有体积云，也没有镜头光晕 | 用 takram 体积云，并有镜头光晕 | 天光干净，但缺少云影和逆光 |

许可边界：Google、Esri、Mapbox、百度的航拍和街景不能再分发。OpenAerialMap 在这一带大约只有 1 公里分辨率。要接近东京的贴图，只能找可再分发的航拍，或者继续把程序化立面做得不像重复贴片。

## 建模精细度

| 差距 | 现在 | 东京那边的做法 | 看出来的现象 |
| --- | --- | --- | --- |
| 普通楼是脚印挤出 | OSM 轮廓加层数或默认高度。屋顶只有穹顶、尖顶、四坡、洋葱顶几类。**已加**：百米以上的塔每 15–18 层一道避难层百叶；去掉了凭空加的裙房退台；同一座塔的各部件共用立面 | LOD2 实测体块，屋顶是测出来的 | 体量对，转折、退台、设备层大多没有 |
| 地标是手写外壳 | 上海中心、金茂、环球金融中心等是程序形体，有楼板和核心筒。**已修**：金茂外壳法线朝外（之前里外反了）、上海中心冠部、和平饭店整栋、中国银行屋顶。仍然不是实测模型 | 这些楼如果在 PLATEAU 里，就是实测网格加航拍 | 远看像，近看能看出对称网格和空的塔身 |
| 墙没有厚度 | 一面墙一个四边形。相机靠碰撞停在墙外，楼里面仍然是空的 | 实测网格至少是闭合的外壳，远处还有粗模 | 贴着玻璃看，像一张贴图而不是一栋楼 |
| 路和地形被简化 | 车按道路中心一条线开，没有展开真实车道，也不会变道。高程被压成平原，避免雷达把塔扫成小山 | 地形来自实测 DEM，路网更接近真实断面 | 外滩车道是按断面加宽的特例，别的街仍然细；地面缺少真实起伏 |
| 地铁不进地下 | 列车贴在地面或略高的路径上 | 轨道可以落到真实高程，含地下段的取舍 | 列车像浮在路上 |

## 统筹

东京是一条数据管道：同一套 PLATEAU 瓦片同时决定形体、贴图、LOD 和加载范围，远近是同一栋楼的粗细两档。上海现在是四套东西拼在一起，接缝会露出来。

1. **数据**：OSM 脚印决定大多数楼。高度表和 `building:part` 只修正一部分。
2. **地标**：二十来栋手写模型，和旁边的挤出楼不是同一套精度。
3. **贴图**：CC0 平铺、立面照片、纯着色器窗格三种外观，按高度和用途切换，切换本身就能看出来。
4. **加载**：建筑按 256 米流式加载，路网和地形却是整区一次读入。精细度不随距离降，只随「在不在视野附近」整块出现或消失。

所以性能、贴图和模型上的差距会叠在同一个画面里：近处地标、中景挤出楼、重复贴片、全精度网格和整城倒影同时在算。

## 已经做了的（2026-10）

### 第一轮：性能

按上面的先后顺序，先做了不换数据源就能做的性能部分。同一台机器（AMD 核显，1024×768），一帧含阴影图更新、江面倒影和后处理，`gl.finish()` 计时：

| 机位 | 之前 | 现在 |
| --- | --- | --- |
| 俯瞰（约 700 块瓦片） | 约 140 ms，约 32000 次绘制 | 约 15 ms，约 700 次绘制 |
| 外滩 | 约 110 ms，约 28000 次绘制 | 约 4 ms，约 450 次绘制 |

- 地标和桥按材质合并：九千多个小网格并成一百多个，几何不变，可以视锥剔除。
- 地形切成 1 公里见方的块，按距离换 1/2/4/8 格的索引，块间用裙边盖住缝；不在视野里的块不画。
- 远处 4×4 块瓦片（约 1 公里）的楼、地面、道路、水面各并成一个网格，近处再拆回逐块。几何相同，切换没有跳变。
- 路灯、信号灯、招牌、屋顶设备超过约 1.1 公里隐藏；地面、道路和这些小件不进江面倒影。
- 车和行人只画相机附近的（车 1.6 公里，人 650 米），颜色跟着车走，不跟槽位走；跟车计算从每车 `indexOf` 改成线性。
- `roads.json` 不再挡首帧：先出地形和楼，路网到了再补人行道底色、再发车。相机先就位再请求瓦片，第一批请求的就是视野里的块。
- 顺手修了：`applySun` 提前 `return` 导致曝光、调色和夜景灯光不随时刻同步；跳机位会被「不穿墙」检查拦在半路；静态构建里没有 `.tile` 文件。

### 第二轮：建模

先逐个近看地标，和实楼对照，挑出最不像的改：

- **金茂大厦**：八角塔身的面是朝里卷的，单面材质把朝向相机的一侧剔掉了，看到的是背面的内壁和中间的深色核心筒，所以每个立面中间都有一条黑带。现在外壳和退台平台都朝外，塔身是银灰色的宝塔分段。夜里改成暖色窗灯加淡银色泛光，不再整栋发白，冠部仍是金色。
- **上海中心**：顶上原来是收成一点的格构锥，像针尖。实楼的外幕墙一直延伸到顶，冠部宽度几乎不收，顶边朝凹槽一侧斜着升高。现在冠部是 30 根竖肋加 5 道环，宽度接近塔身，顶边斜切，最高点在凹槽那侧。
- **和平饭店**：OSM 脚印是沿南京东路约 150 米长、临外滩一端收窄的楔形，原来只在楔形中心立了一个 28 米宽的塔，周围被隐藏的脚印成了空草地。现在整块楔形是约 10 层的花岗石楼（勒脚、腰线、檐口、每条边一排窗），带绿铜方锥的塔楼移到临外滩的窄端，和沙逊大厦的实际位置一致。
- **中国银行大楼**：原来是又高又尖的锥顶。实楼是低坡的蓝绿琉璃庑殿顶，现在改成带出檐的四坡顶和短正脊。
- 编译时在 manifest 里给每个地标带上 OSM 轮廓（`ring`），不是塔的地标可以按轮廓建整栋。改了以后要重新 `npm run compile`。

普通楼：百米以上的塔每 15–18 层有一道避难层/设备层，窗换成深灰百叶，夜里不亮，塔身分成一节一节，不再是一根均匀的玻璃柱。

### 第三轮：东方明珠、金茂和夜景

对照公开的结构数据（[凤凰网](https://news.ifeng.com/c/7i5hGcS1Uy6)、[Structurae](https://structurae.net/en/structures/oriental-pearl-radio-television-tower)）和宣传片里常见的夜景重做：

- **东方明珠**：原来的小球是挂在立柱外侧、只有两层，另有一堆领圈、细环和斜撑横杆，柱子像镀铬管。现在按实际结构：三根 9 米立柱从基座到上球，两球间五层 6 米横梁，每层横梁中间一个 12 米小球；三根 7 米斜撑 60° 落地；天线分段收细。去掉了领圈、多余的环和横杆，构件少了一大半。立柱是哑光米白混凝土。球面去掉了每块玻璃随机的亮暗和反光，窗格线抗锯齿并随距离淡出，不再像碎砖。夜里立柱变暗，每根三条竖向灯带加接缝灯环，球面是均匀的 LED 点阵。
- **金茂大厦夜景**：原来是整栋发白的窗格。现在每段由挑檐上的泛光往上打、越往上越暗，挑檐是一圈暖光，顶上尖塔最亮。
- **上海中心、环球金融中心夜景**：原来整层整层地亮或灭，成了黑白斑马条。现在和其他塔一样按窗随机亮，少数楼层整层亮着。

### 第四轮：普通楼的断层

近看陆家嘴的普通塔楼，底部约 18 米处有一道凭空加出来的「裙房」：塔身整体往里缩一截，留下一条没有收边的平台，上下两段的窗格按各自的墙长排列，对不上缝，夜里尤其明显；62% 高度处还有第二道。这是程序加的，不是数据里的。现在去掉了，塔身一整段直上。

OSM 里很多塔被拆成几个 `building:part`，每个部件原来各自随机立面、颜色和窗距，拼起来像几栋楼叠在一起。现在平面重叠的部件归成一组，用最高那个部件的样式和颜色，楼层从整组最低处算起，窗格、避难层和夜景亮灯在部件之间连续。

### 第五轮：按宣传片机位对照后的修改

先按宣传片常用的 12 个机位截图、打相似度（外滩望陆家嘴、陆家嘴望外滩、河湾航拍、仰视三塔、明珠仰视、外白渡桥，各取白天/黄昏/夜），再按差距逐项改：

| 项目 | 改前 | 改后 |
| --- | --- | --- |
| 黄浦江水色 | 深蓝、像海 | 白天是泥沙的黄褐偏绿，倒影也带一层水色；夜里仍深 |
| 夜间航拍倒影 | 高空俯拍时近处江面出现错位楼群 | 夜里加宽的倒影视野和外滩倒影的上提只在低机位起作用，随相机高度退回 |
| 夜景色温 | 远处窗灯一律淡化成同一种琥珀色，整片天际线发橙 | 办公楼以冷白为主、少数偏暖，住宅偏暖 |
| 楼宇轮廓灯 | 只有约两成高楼有，且很淡 | 约一半百米以上的塔有竖角线和冠部灯线，白、冰蓝为主，少量金色和场景色 |
| 名楼外观 | 全部随机立面 | `src/shared/towers.js`：花旗、震旦为整面 LED 媒体幕墙（一种主题色+滚动文字条）；中银、国金、汇丰、招商局等白色轮廓；交银、未来资产蓝色轮廓；香格里拉金色冠；白天各给真实的玻璃色调 |
| 名楼名称 | 被 `building:part` 覆盖的轮廓连同名字一起丢掉，花旗、震旦、中银等在瓦片里都没名字 | 编译时把轮廓的名字传给其中没名字的部件，点击也能看到楼名（需重新 `npm run compile`） |
| 上海中心 | 凹槽是一道黑缝 | 凹槽是稍暗的玻璃凹面；加了九个分区之间的设备层/空中大堂环带，白天浅色、夜里一圈柔光；窗灯偏冷白 |
| 东方明珠 | 立柱离中轴 10.5 米，小球被挡住 | 收到 8.2 米，五个小球在柱间明显鼓出 |
| 外白渡桥 | 单跨银色圆管拱桁架 | 两跨驼峰式下承钢桁架、中墩、方形构件、深灰，夜里沿桁架亮暖光 |
| 外滩夜景 | 绿铜顶夜里几乎不亮 | 和平饭店、中国银行的绿铜/琉璃顶加泛光 |
| 黄昏 | 太阳落山前后一直蒙着暖褐雾 | 只在日落前后几度有薄暖雾；日落后是干净的蓝调，天空偏深蓝 |

补充：航拍夜景里主干道和次干道远看会亮成连续的橙色路网（路灯光照贴图在高空只有一两个像素宽，单靠它街道会发黑）；夜空和地平线再往深蓝调了一点。后续可以交出去做的任务列在 `docs/grokbot-tasks.md`。

核对过的一点：外白渡桥下的「褐色地面」其实是水面，只是黄昏暖雾把它染成了土色，不是缺水。

另外，本机 Node 升级到 24 后 `node --test 目录` 不再可用，`npm test` 改成 `tools/tests/run.mjs` 自己列出测试文件，Node 20 和 24 都能跑。

还没动：立面照片（第 3 条，本地没有 `npm run textures` 的纹理，看不到效果）；环球金融中心和东方明珠对照下来大体对，没改；白玉兰广场顶上的平台和实楼不太一样，没有把握，没改。

OSM 真实颜色和材质：`heights.js` 的颜色解析支持颜色名（含 dark/light/pale 前缀、下划线写法）、`#rrggbb`、`#rgb` 和不带 # 的六位十六进制；没有 `building:colour` 时按 `building:material`（brick、stone、concrete、metal、plaster、wood 等）给墙色，都没有才走原来的随机色；glass/mirror（以及 glass;steel）照旧标 `BFLAG.GLASS`。`roof:colour` 值得加：瓦片格式升到第 3 版，每栋楼多一个 u32 屋顶色（第 24 位表示有标注），`meshbuild.js` 的平顶和坡顶优先用它；旧瓦片会报「tile version 2, expected 3 … run npm run compile」。统计（`npm run compile` 会打印）：外滩区 11961 栋里 106 栋有颜色或材质标签，35 栋有 `roof:colour`，覆盖率不到 1%，所以整体观感变化很小。验证：`npm test` 里的 `OSM colours parse from names, hex and short hex` 和 `tiles carry the roof colour and old tiles fail clearly`；白天外滩望陆家嘴 `?cam=-1095,22,-40&look=0,170,40&up=1&traffic=0&time=11` 和俯看浦西 `?cam=-300,160,250&look=-1000,20,-300&up=1&traffic=0&time=11`。

## 建议的先后顺序

不改数据源也能做的，放前面。依赖新数据的放后面。

1. ✅ 远景楼用更粗的网格或合并墙面，让精细度随距离降，而不是只靠少加载几块。（远处按 1 公里块合并）
2. ✅ 倒影、环境光遮蔽、阴影在相机移动时继续保持降档；静止时再拉回现在的画质。（原来就有，这轮减少了每一档要画的东西）
3. 立面不要整墙重复同一张照片：按楼层错位、换色、混用程序化窗格，高塔优先走程序化而不是切片。（着色器里已有按两层错位翻转、高办公楼走程序化；还没拿纹理实看）
4. 🟡 地标补上分层楼板和核心筒之后，再加一档更近的细节（退台、幕墙分缝），仍然不要做成空壳。（东方明珠按结构重做；金茂、上海中心、和平饭店、中国银行已修；其余未动）
5. ✅ 路网按视野使用，不要为了发车先解析整个 `roads.json`。（首帧后再用；还没有按块切路网）
6. 航拍和实测网格以后再说。没有可再分发的数据时，不要用街景或商业卫星图填这个缺口。
